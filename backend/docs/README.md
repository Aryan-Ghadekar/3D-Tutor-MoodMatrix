# MoodMatrix Backend Documentation

This folder documents every feature of the backend: what it does, how it works internally, how to call it,
how to configure it, and how to test and extend it.

The backend is two independent services:

| Service | Folder | Default port | Stack | Required? |
|---|---|---|---|---|
| **FastAPI service** | `backend/fastapi-service` | **8001** | Python 3.10+, FastAPI, pdfplumber, python-pptx, Whisper, sentence-transformers | **Yes**. All AI features live here |
| **Express API** | `backend/src` | 5000 | Node 18+, Express 5, Sequelize (optional MySQL) | No. Logs cognitive-load / help-offer events; the web UI does not depend on it |

> The documentation is mostly about the FastAPI service because that is where the product's features are.
> The Express API is covered in [features/express-service.md](features/express-service.md) and
> [api/express.md](api/express.md).

## Quick start

```bash
cd backend/fastapi-service
python -m venv venv && source venv/bin/activate       # Windows: venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env                                   # add OPENROUTER_API_KEY
python main.py                                         # http://localhost:8001
```

Interactive API explorer (generated by FastAPI): <http://localhost:8001/docs>.
The same schema is committed as [openapi.json](openapi.json).

```bash
curl http://localhost:8001/health          # {"status":"healthy"}
curl -F "ppt=@lecture.pptx" http://localhost:8001/analyze-lecture
```

## Keeping this documentation accurate

* `openapi.json` is generated. After changing an endpoint or a request model run
  `python backend/fastapi-service/export_openapi.py`.
* Example payloads in these docs were captured from the running service (with the LLM mocked), so field
  names and shapes are real. If you change a response shape, update [reference/data-models.md](reference/data-models.md).
* The behaviours described here are covered by the automated tests (65 backend tests plus browser end-to-end
  scenarios in `e2e/`); see [guides/testing.md](guides/testing.md) for which test protects which behaviour.

## Conventions used in these docs

* "**the LLM**" means the chat model reached through OpenRouter (`OPENROUTER_MODEL`).
* "**degrades gracefully**" means the feature still returns a useful result without the optional component
  (AI key, Whisper, embeddings, network). Each feature doc has a *Failure modes & fallbacks* section.
* Times and sizes quoted (timeouts, limits, retention) are constants in the code; the doc names the constant
  so you can find and change it.
